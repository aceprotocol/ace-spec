# Signing Scheme: ed25519

## Overview

| Property | Value |
|----------|-------|
| Scheme ID | `ed25519` |
| Algorithm | Ed25519 (EdDSA over Curve25519) |
| Key size | 32 bytes (public), 64 bytes (private) |
| Signature size | 64 bytes |
| Address format | Base58 (Solana-style) or hex |
| Typical chains | Solana, general-purpose |

## Address Derivation

```
publicKey[32 bytes] → Base58Encode(publicKey) → address
```

Example: `5Ht7RkVSupHeNbGWiHfwJ3RYn4RZfpAv5tk2UrQKbkWR`

## Signing

```
signData = SHA-256(length-prefixed envelope fields)  // See 04-messages.md
signature = Ed25519.sign(privateKey, signData)
encoded = Base64(signature[64 bytes])
```

## Verification

```
signData = SHA-256(reconstructed length-prefixed fields)
publicKey = Base58Decode(sender.address) → 32 bytes
valid = Ed25519.verify(publicKey, signData, Base64Decode(signature))
```

**Public key source:** For Ed25519, the `address` field IS the Base58-encoded public key, so it is the authoritative source. If `signingPublicKey` is also present in the registration file, implementations SHOULD verify that `Base64Decode(signingPublicKey) == Base58Decode(address)` and reject the registration if they differ.

## Address Normalization

Base58 addresses are case-sensitive. No normalization is applied.
