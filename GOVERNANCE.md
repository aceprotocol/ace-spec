# Governance

ACE's normative specification, profile contracts and conformance vectors are public review artifacts. Operating a relay, SDK or hosted service does not grant protocol authority. Any party can implement ACE, operate a relay, propose a profile or participate in review.

Repository maintainers merge reviewed changes and publish tested release combinations. Their responsibility is to document rationale, respond to interoperability objections, and distinguish normative requirements from one operator's defaults. Contributions do not transfer ownership of an independent deployment to these maintainers. Current maintainers are the repository collaborators; this document does not claim an elected council or a voting process that has not been established.

A specification change is proposed in a public issue or pull request. Substantive wire/security changes require a written problem, threat model, alternatives, migration/versioning consequences once released, shared positive/negative vectors, and evidence from independent implementations. Maintainers record resolution in the merged discussion; unresolved objections stay visible. Disputes may be raised as a separate governance issue with concrete proposed text.

The `ace:` namespace identifies profiles maintained with this specification. Third parties use their own controlled namespace. Installing a profile is always local policy, never a requirement imposed by the public directory. Adoption is demonstrated by compatible implementations and use, not by compulsory registration with one organization.
